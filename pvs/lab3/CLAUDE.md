# ЛР3 «OLED-дисплей и устройства I2C», вариант 3 «Уровень»

Стенд SDK-1.1M, процессорный модуль SDK-1.1MC.427: STM32F427VIT6.

## Как работаем (пожелания пользователя)
- Всё делаю сам; пользователя прошу только о физических действиях (нажать кнопку, повернуть стенд) и говорю об этом явно.
- Прошивка на C. Отчёт не нужен, нужен только работающий код.
- Свой терминал не пишу. Для ручной проверки UART используется PuTTY:
  `%LOCALAPPDATA%\Programs\PuTTY\putty.exe -load SDK-1.1M` (сессия в реестре: COM3, 115200 8N1).
  PuTTY держит COM3 открытым, перед своими обменами с портом его нужно закрыть.
- Коммитить только по просьбе. Корень git: `C:\ITMO_University`. `fw/build/` в git не добавлять.

## Задание (пособие, раздел 5.3; полный текст: docs/manual_lab3_sections.txt)
На стенде, датчик LSM9DS1 (акселерометр) по I2C:
- на OLED постоянно выводятся текстом ускорения по трём осям и графический указатель одного из двух
  типов: стрелка-вектор вниз (направление силы) или линия горизонта (перпендикулярно ей);
  по умолчанию горизонт;
- тип указателя переключается командой клиентской программы.

Клиентская программа на ПК (язык любой):
- GUI или TUI; интерфейс с вводом команд строкой запрещён;
- имя COM-порта задаётся аргументом командной строки;
- сразу после подключения отправляет «пинг», чтобы убедиться, что стенд отвечает;
- постоянно показывает то же, что и стенд: значения по осям и указатель того же типа, что сейчас на стенде;
- позволяет выбрать тип указателя и отправить его на стенд;
- пишет в файл журнала все данные, переданные по UART в обе стороны, с меткой времени у каждого сообщения.

Общие требования:
- протокол обмена придумываем сами;
- драйвер UART на стенде любой из двух (по прерыванию или по опросу), поддерживать оба не нужно;
- дисплей и датчик на одной шине I2C: транзакции не должны пересекаться. При работе по прерываниям
  обновление видеопамяти (самая длинная транзакция, около 1 КБ) встраивается в расписание обмена с датчиком;
- начальная инициализация дисплея и устройств выполняется опросом, до включения прерываний.

Бонус: матричная клавиатура как второй способ управления. Требования к ней:
- защита от дребезга;
- нажатие фиксируется сразу, а не при отпускании;
- удержание не даёт повторных нажатий;
- при нажатии больше одной кнопки считается, что не нажата ни одна;
- кнопкам назначены коды 1..12.

## Аппаратура
I2C1:
- PB8 = SCL, PB9 = SDA, AF4; 400 кГц, DutyCycle 2, 7-битная адресация;
- в HAL адреса 8-битные (адрес уже сдвинут влево);
- для регистровых обменов HAL_I2C_Mem_Write/Mem_Read с MemAddSize = 1.

Адреса устройств на шине (8-битные):
| Устройство | Адрес | Примечание |
|---|---|---|
| OLED WEO012864DL (контроллер SSD1306) | 0x78 | |
| PCA9538 | 0xE0 | P0 = сброс дисплея; входы прерываний устройств |
| PCA9538 | 0xE2 | клавиатура |
| LSM9DS1 акселерометр/гироскоп | 0xD4 при SDO_A/G = 0, 0xD6 при SDO_A/G = 1 | см. ниже |
| LSM9DS1 магнитометр | 0x38 / 0x3C | не нужен |

Адрес LSM9DS1 0xD4 (на схеме SDO_A/G на GND) проверен на стенде: WHO_AM_I = 0x68.
Оси датчика относительно экрана измерены на стенде: +X вправо, +Y вверх по экрану; лёжа дисплеем вверх Z = −1g.

LSM9DS1, акселерометр (docs/lsm9ds1.pdf):
- WHO_AM_I (0x0F) = 0x68;
- CTRL_REG6_XL (0x20): ODR_XL в битах [7:5] (001 = 10 Гц, 010 = 50, 011 = 119, 100 = 238 Гц),
  FS_XL в битах [4:3] (00 = ±2g, 0,061 mg/LSB; 10 = ±4g; 11 = ±8g; 01 = ±16g).
  Запись только в CTRL_REG6_XL включает один акселерометр, гироскоп остаётся выключенным;
- CTRL_REG8 (0x22): BDU = бит 6, IF_ADD_INC = бит 2 (по умолчанию 1, т.е. автоинкремент адреса), SW_RESET = бит 0;
- STATUS_REG (0x27): XLDA = бит 0;
- OUT_X_L_XL..OUT_Z_H_XL (0x28..0x2D): int16, младший байт первым;
- выходы INT1_A/G, INT2_A/G, INT_M, DRDY_M тоже есть.

PCA9538 (docs/PCA9538.pdf), регистры:
- 0 = вход;
- 1 = выход;
- 2 = инверсия полярности;
- 3 = конфигурация (1 = вход; после сброса все выводы входы).

OLED, SSD1306 (docs/SSD1306.pdf, пособие 1.8):
- первый байт посылки — управляющий: 0x00 = команды, 0x40 = данные;
- сброс: P0 у 0xE0 сначала в 1, затем импульс 0 не короче 1 мкс, после него пауза около 1 мс;
- инициализация одной транзакцией с 0x00:
  `AE, 20 00, C8, 40, 81 FF, A1, A6, A8 3F, A4, D3 00, D5 F0, D9 22, DA 12, DB 20, 8D 14, AF`;
- сброс указателей перед записью кадра: `21 00 7F`, `22 00 07`; затем 1024 байта с 0x40;
- видеопамять: 8 страниц по 128 столбцов, бит D0 = верхний пиксель столбца в странице.

Клавиатура (PCA9538 0xE2):
- строки на P0..P3, столбцы на P4..P6, столбцы подтянуты к 1;
- опрос строки: на неё выдаётся 0, остальные строки остаются входами, затем читаются столбцы (0 = нажата);
- на каждую строку два обмена I2C.

Из ЛР1 и ЛР2, уже в коде:
- USART6: PC6 = TX, PC7 = RX, AF8, 115200 8N1; на ПК это COM3 (FT2232, интерфейс B);
- кнопка PC15 (активный 0);
- светодиоды PD13 (зелёный), PD14/PD15 (двухцветный).

Тактирование: HSE 25 МГц, PLL до 180 МГц, APB1 45 МГц (на нём I2C1), APB2 90 МГц.

## Код (fw/), каркас из lab2
- `board_pins.h`: все номера выводов, адреса I2C, ориентация акселерометра.
- `board`, `gpio_hw_hal`: инициализация, светодиоды, кнопка, UART, I2C (с освобождением шины), таймер TIM6.
- `fifo`: SPSC lock-free.
- `serial` + `uart_hal*.c`: драйверы по прерыванию и по опросу; `serial_write` пишет всё или ничего.
- `console`: `console_message` с printf.
- `i2c_bus`: HAL I2C; опрос при инициализации, затем прерывания; сторож зависания.
- `i2c_sched`: TIM6 1 мс, цикл 20 тактов: 8 тактов клавиатура, 1 акселерометр, 11 дисплей (части кадра по 32 байта).
  Счётчики `i2c_bus_stats`, `i2c_sched_stats` читаются отладчиком.
- `accel` (LSM9DS1), `keypad` (PCA9538 0xE2), `oled` (SSD1306, двойной буфер), `gfx` + `font5x7`.
- `level`: указатель и экран, `proto`: протокол (описан в proto.h), `app_main.c`: главный цикл.
- Кнопки клавиатуры: 1 = горизонт, 2 = стрелка; коды 1..12 по строкам сверху вниз.

## Клиент (client/level_client.py)
- `py -3 client/level_client.py COM3 [--log файл]`, tkinter + pyserial; журнал `level_<дата>_<время>.log`.

## Сборка и прошивка (Git Bash)
- `sh tools/build_fw.sh` собирает fw/build/lab3.elf. Тулчейн: Arm GNU 14.2; HAL берётся из `../lab1/third_party/STM32CubeF4`.
  Предупреждения `_read/_write is not implemented` от nosys — норма.
- `sh tools/flash.sh [erase]`: OpenOCD xpack 0.12, конфиг `fw/openocd/SDK1_1_M FTDBG.cfg`.
  Подключение под сбросом с перехватом вектора сброса.
- Если OpenOCD пишет LIBUSB_ERROR_NOT_FOUND, интерфейс A FT2232 снова на драйвере FTDIBUS. В ЛР2 помогла
  принудительная установка WinUSB (oem63.inf) через UpdateDriverForPlugAndPlayDevices с INSTALLFLAG_FORCE; нужно подтверждение UAC.
- Память работающего стенда читается без остановки ядра: `reset_config connect_deassert_srst` и tcl с `read_memory`.
